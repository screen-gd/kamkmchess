# Browser module responsibilities

This is the foundation module map for [Establish the React/TypeScript application and build checks](https://linear.app/kamkm/issue/KHA-26/establish-the-reacttypescript-application-and-build-checks). The canonical architecture is the [architecture resolution](https://linear.app/kamkm/issue/KHA-13), originally comment `64e0511f-3e26-4b79-a3c8-4f834605736c` and amended for stack choices by owner comment `7e9599bd-2143-49fa-b139-8018a25cbeb7`. The approved specification's [module handoff](../spec/mvp-handoff.md#implementation-sequence-and-module-handoff) identifies the test seams.

The app has a playable local board in `src/ui/`, a strict `src/rules/` adapter, pure `src/clocks/` calculations, proof checker and search, `src/archive/`, `src/storage/`, provider connection and protocol modules, and a serialized `src/controller/` core. KHA-32 adds controller proof settlement and the bounded runner in `src/adjudication/`, connected by `src/adjudication-controller/`. KHA-36 adds completed-answer classification and per-turn recovery budgets in `src/moves/`. KHA-53 sends typed turn effects to the controller, which checks request fences and remains the sole authority for move acceptance, clocks and results. The redundant move reply fence module has been removed. Hosting and account infrastructure are Vercel, the Clerk-authenticated Go API and PostgreSQL.

## Allowed dependencies

The composition module wires adapters into the controller. The UI calls only the controller's game interface. Rules, clocks and archive calculations remain usable without React, network or IndexedDB. Reply classification and turn budgets stay usable without a provider, a controller instance or a browser store. Proof checkers use the orthodox transition interface; Workers do not reach into controller state. Storage and cloud adapters persist explicit versioned records rather than importing UI state. Provider adapters translate wire data without importing React or deciding game outcomes.

Keep public exports small. Import another module through its public entry point when one exists; keep private implementation files local. Enforce these responsibilities in review. No generic event bus, abstract base hierarchy or empty adapter wrappers are needed in the foundation.

## Event and transaction contract

Every asynchronous request/analysis and returned event must carry its game ID, segment ID, position revision, request or analysis generation, and ownership epoch. Include the producing side and connection/configuration revision where applicable. Repeated FENs do not make old work eligible again. Stop, Undo, identity changes, takeover and expiry fence late work.

The serialized acceptance path checks eligibility and the persisted revision, samples decision time immediately before the checkpoint write, and compares the deadline. At the deadline, expiry wins. A completed eligible legal move before it may commit at that effective time. Await transaction completion before presenting acceptance or sending a follow-up request; charge commit delay to the next active clock. An aborted transaction grants no durable move. Preserve operation IDs for uncertain recovery.

The controller alone latches final results. While an exact ending is unresolved, preserve the original position-entry/expiry facts, save pending state, fence play and keep any unexpired active clock running. A later proof can settle an unresolved event at its effective time, never rewrite an accepted final result. Setup pending does not start clocks.

## Persistence and trust

Version storage, checkpoint, archive, proof-search and cloud operation formats in their implementation tickets. Reject incompatible writes and validate restored data before use. Keep guest, account UUID and local credential namespaces separate. The connection store provides per-namespace credential removal; account sign-out must call it and fence pending requests. Sync/export callers must exclude credentials and block a transfer when a recognized credential echo appears. Those caller integrations are outside the connection module.

Provider text is untrusted text. Routine telemetry excludes raw transcripts, secrets, private endpoint configuration and auth tokens. Game sync/export preserves the complete versioned archive through allowlisted DTOs that exclude AI keys, auth tokens, secret headers and secret-bearing endpoint data. A recognized credential echo stays local and blocks the affected sync/export until resolved; never redact the sole exact archive and call it lossless. No administrative key is browser configuration. Vercel serves the static app and Go API. PostgreSQL stores private account data; Clerk supplies identity and sessions. The API never receives AI credentials or relays generation requests.

## Verification seams

Use deterministic fixture tests at the approved controller, rules, clock/checkpoint, archive/replay, connection, protocol and proof-checker interfaces. Test independent expected outcomes, fault/abort injection and stale-event races through those interfaces. Do not test private helper shapes or manufacture placeholder assertions to increase a test count.

Native browser, screen-reader, mobile, deployed account, live-provider and cost runs have separate prerequisites and evidence records. A static build or fixture pass does not certify them.

KHA-53 composes classified model turn effects at the match-controller boundary. Recovery
counts are persisted in the existing `BudgetCheckpointV1` as remaining counts per side:
`illegalMoveAttemptsRemaining` and `manualRetriesBySide` are keyed by side, while
`formattingCorrectionsRemaining` applies to the active model turn. `TurnBudgetsV1` remains
a spent-count value for one pending turn. The adapter derives persisted remaining counts
from each classified effect and resets them when a move advances the turn. Illegal attempt
records are retained in the versioned `move-attempts` checkpoint extension, alongside the
current archive, without changing the storage schema. A nonterminal effect commits the
recovery spend and increments request generation atomically; the next request starts with
the new full controller fence, preserving retry-in-place on the same chess turn. Stop,
expiry and stale fences commit no recovery spend. Final resignation and fourth-illegal
attempt results are latched with the same atomic checkpoint write as their event.
